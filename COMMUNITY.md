# Community and governance

PixelForge Prompt Studio is a small, maintainer-led open-source project for
consistent pixel-art prompts. It is not an image-generation service. The
project values local data ownership, understandable production rules,
accessibility and backward compatibility.

## Where to participate

- [Issues](https://github.com/kleiveist/PixelForgeStudio/issues): reproducible
  bugs, focused feature proposals and usage questions.
- [Pull requests](https://github.com/kleiveist/PixelForgeStudio/pulls): reviewed
  code, documentation, tests and translations.
- [GitHub releases](https://github.com/kleiveist/PixelForgeStudio/releases):
  official release notes, artifacts, limitations and upgrade guidance.
- [Private vulnerability reporting](SECURITY.md): security findings only.

There is no official Discord, paid support channel or external community
server. Repository Issues and pull requests are the supported channels;
unrelated projects using similar names are not affiliated. Follow
[support guidance](SUPPORT.md) and the [code of conduct](CODE_OF_CONDUCT.md).

## Decisions and maintenance

Repository owner [@kleiveist](https://github.com/kleiveist) is the current
maintainer and release steward. Contributors can propose changes through
issues and PRs. Maintainers make final scope, merge and release decisions,
explaining technical tradeoffs in the relevant issue. No proposal, donation
or patch purchases priority or guarantees acceptance.

Changes to persisted data, dependencies, privacy behavior or hosting require
explicit review and regression evidence. Releases are gated by tests and a
documented security/artifact review. Larger changes should begin as a design
issue, not an unrequested rewrite. Additional maintainers may be invited
after sustained contributions and agreement on these responsibilities.

Support and security triage are volunteer, best-effort activities, with no
SLA or fixed response deadline. The [security policy](SECURITY.md) defines
supported versions. Do not depend on an issue response for emergency recovery:
keep tested local JSON backups.
